# Server API contract (draft)

This is a proposed contract for the headless NX-Pctl-Manager sysmodule. It is not yet implemented by a server.

## Transport

HTTPS REST handles enrollment, authentication, complete policy snapshots, heartbeats, event batches and acknowledgements. WSS handles low-latency policy updates and events. TLS certificate and hostname validation are mandatory; no plaintext or accept-all-certificate mode is allowed.

## Device identity

Each console has a unique device ID and unique provisioned credential. Never embed a shared API key in the repository or firmware image. Enrollment should use a short-lived, single-use code generated by the server and explicitly paired by an administrator. Credentials must be revocable and rotatable.

The credential is distinct from policy data. Its persistent storage and recovery mechanism must be validated against the chosen Atmosphere release.

## Proposed REST endpoints

- POST /v1/devices/enroll — consume a one-time enrollment code.
- POST /v1/devices/auth — authenticate device credential and return a short-lived access token, server time and capabilities.
- GET /v1/devices/{device_id}/policy — return a complete snapshot containing schema_version, device_id, revision, issued_at, expires_at, server_time and policy.
- POST /v1/devices/{device_id}/heartbeat — report module/firmware versions, uptime, current revision and health counters.
- POST /v1/devices/{device_id}/events:batch — accept bounded events with unique IDs and per-device sequence numbers; deduplicate retries.
- POST /v1/devices/{device_id}/policy-ack — acknowledge accepted revision and application status.

## Proposed WebSocket events

- policy.updated — full snapshot or delta with explicit base_revision.
- policy.revoked — force a fresh REST fetch.
- command.requested — strict allow-list of reversible actions only; never execute arbitrary code, shell commands or filesystem paths.
- server.ping / client.pong — keepalive.

## Client validation

Accept only complete authenticated snapshots bound to this device. Reject schema mismatches, revision rollback, invalid timestamps and out-of-range values. Replace the RAM snapshot atomically. During network loss, enforce the last accepted snapshot. After module restart offline, enter restricted bootstrap because the RAM snapshot no longer exists.

Queue events in bounded RAM only; do not add a local usage database or persistent event spool. Never log tokens, enrollment codes, credentials, PINs or TOTP material.
